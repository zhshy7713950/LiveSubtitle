# 任务交接模板

复制为 `docs/tasks/handoffs/TASK-XX.md`，只创建自己的文件。提交前把测试输出中的内容、Key、设备标识和个人路径清除；原始长日志留本机，不加入公开仓库。

```markdown
# TASK-XX 交接

- 基线 commit：
- 任务分支 / commit：
- 前置报告：
- 状态：待审查 / 未完成（不得用“已完成”代替具体证据）

## 改动

- 实现、文件和用户可见行为：
- 对外具体类型、initializer、协议遵守情况：
- 流的有界策略、取消／终止和资源释放：

## 验证

| 命令或设备步骤 | 环境 / 用例数 | 结果 | 未通过原因 |
| --- | --- | --- | --- |
| scripts/verify.sh | | | |
| scripts/test.sh ... | | | |
| 任务卡逐项验收 | | | |

## 契约请求

- 无 / 原签名、新签名、理由、消费者、兼容影响、所需测试：

## 未验证与已知问题

- 真实设备／系统组合中尚未验证的行为：
- 阻断合并的问题及证据：
- 集成人需要的装配、生命周期和运行配置：
```

集成人审查文件是否越界、关键边界用例是否执行、报告与源码是否一致。合并后执行工程检查和现有全量测试，不能只依赖单任务的“通过”文字。
