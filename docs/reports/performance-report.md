## 延迟记录口径

使用固定非敏感英文素材；登记素材类型、URL、版本/文件摘要或直播时间范围、精确语言标签、设备/系统/Chrome/App commit、网络条件。至少 100 个真实分段，预先确定冷热启动及本地/AI 的分组，不能把不同网络/模型的 AI 结果合并成一个承诺。

| 数值字段（不含正文） | 口径 |
| --- | --- |
| 本轮随机编号 / 段序号 / 代次 / sourceRevision / provider | 只作当前取样关联；不记录真实用户标识或完整 endpoint |
| captureArrival / speechInput | 同一自有音频范围在客户端到达和交给识别输入的单调时刻 |
| referencePhraseEnd / firstSourceVisible | 参考短语音频结束经 PTS 映射到单调时间；首次可见原文确实包含该短语 |
| segmentAudioEnd / firstValidTranslationVisible | 段音频结束至首个有效译文实际可见；不能改用 job 创建时间 |
| jobCreated / HTTPFirstText / renderAccepted / frameEnqueued | 另列调度、服务、渲染阶段；不能用其替代总体首次可见 |
| deadline / outcome / drop / timeout | 成功、修订取消、旧结果、失败、超时、丢弃单独计数，不从分母静默剔除 |
| audioQueuedSeconds / inFlightSeconds / pendingJobs / activeAI / activeLocal | 最大值、分布及丢弃/断流次数，结合持续时间判断长期积压 |

P95 使用有效延迟样本排序后的第 `ceil(0.95 × n)` 项（从 1 开始）；n=0 输出 N/A，n<100 只能给“样本不足”的描述，不能标达标。每类指标同时列全部尝试数、成功有效数、失败/超时/缺失数及最大值。保持正式方案 §16.1 的起点，跨源/识别/显示使用同一时钟映射，不把负值或缺配对样本当作 0 ms。

停止后新作业的区间从协调器 Identity 失效开始，检查所有后续创建/发送记录；主动取消与旧故障分开。精确六秒和首文本超时由注入时钟回归，不用真实 sleep 六秒制造单元测试时长。
