# 基础框架交付边界

日期：2026-11-02。依据：[正式开发方案 v1.0](development-spec.md)。本文件只细化本次框架搭建，不改变产品设计。

## 本次交付

- 一个 iOS 27.0 / Swift 6 App target、一个纯逻辑单元测试 target、共享 scheme、集中构建配置。
- 可启动的说明性空壳；无开始采集、下载、联网、识别、翻译或 PiP 行为。
- 不依赖 Apple 媒体对象的 Sendable 值类型、模块协议、集中初始参数；不提前实现业务算法。
- Codex 的 AGENTS.md、用户要求的 AGENT.md 兼容入口、Claude Code 的 CLAUDE.md，共用一份项目约束。
- 模块所有权、任务依赖、独立验收、合并顺序、交接模板及 G0 真机报告模板。
- 初始化 Git，关联用户指定的 SSH remote，提交并推送；保留原有设计文档。

## 工程方式

采用原生 Xcode 工程与文件系统同步目录，不额外引入 XcodeGen、第三方包或多个 Swift Package。模块通过协议隔离，仍位于同一个 App 模块内；新增模块内部文件不需要多人同时编辑 project.pbxproj。

相比仅创建空目录，此方案能提前检查 Swift 6 类型和接口；相比预先实现带假结果的服务，它不会让调用方误以为采集或回退已经可用。当前需求已经指定沿用正式方案，因此不另选技术路线。

接口集中在 LiveSubtitle/Contracts，SDK 适配及实现分别落在各职责目录。媒体引用留在适配层；跨执行域只传拥有数据所有权的值。协议只是项目内部约定，不代表同名系统 API。

## 本次顺序

1. 建立配置、App 入口、测试编译入口和共享 scheme。
2. 落地设计中的值模型、协议及初始参数；业务目录只留占位文件。
3. 编写约束、模块契约说明和按文件所有权拆分的任务卡。
4. 执行工程解析、设备和模拟器构建、测试 target 编译及文档检查，记录真实结果。
5. 检查提交范围，提交并推送到远端 main；不强制覆盖已有历史。

## 证据边界

框架可以编译不代表 G0 通过。签名、iPhone 安装、系统全屏共享、Chrome 音频、本机模型和十五分钟后台 PiP 均留给后续任务。未运行的单元测试和真机测试不得记为通过。
